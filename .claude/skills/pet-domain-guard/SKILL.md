# pet-domain-guard

## 트리거 조건
- `post-writer`가 S6에서 본문을 쓸 때 (규칙을 지키며 쓰기 위해)
- `quality-auditor`가 S7에서 검증 항목 6("반려동물 안전 위반")을 확인할 때 (규칙 위반 여부를 대조하기 위해)

## 구조 원칙
**규칙 본문은 이 파일에 하드코딩하지 않는다.** 실제 규칙 목록은 `/references/rules.md`에 둔다. 이렇게 분리해두는 이유는 다른 니치(예: 고양이)로 블로그를 확장할 때, 이 스킬 폴더를 복사한 뒤 `/references/rules.md`만 새로 써서 재사용할 수 있게 하기 위함이다. **지금은 반려동물(강아지) 전용 구조를 그대로 유지하며, 범용화 리팩터링(스킬 이름 변경, 니치 자동 분기 로직 추가 등)은 하지 않는다.** `blog-profile.yaml`의 `niche` 값과 이 스킬의 연결은 향후 다른 니치가 실제로 생겼을 때 다시 설계한다.

## 사용 방법
1. `/references/rules.md`를 읽는다
2. S6에서는 본문 작성 중 해당 규칙에 걸리는 표현을 쓰지 않는다
3. S7에서는 초안에서 규칙 위반 문장을 찾아 `03_audit.md` 검증 항목 6에 그대로 인용한다

## 실패 처리
S7에서 위반이 발견되면 항목 6은 위반 0건이 성공 기준이다 — 경고 허용 항목이 아니다. 위반 시 `post-writer`로 재작성 지시가 간다 (S7 실패 처리 정책과 동일, 최대 2회).
