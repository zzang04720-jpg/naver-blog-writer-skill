## 1. 작업 컨텍스트

### 1.1 배경

네이버 블로그를 강아지 주제로 운영 중이며 애드포스트 승인을 목표로 발행량을 쌓는 단계다. 현재는 사람이 기사를 찾아 붙여넣고, 외부 LLM에 긴 지침서를 넣어 초안을 받고, 이미지 프롬프트를 받아 별도 도구에서 이미지를 만든 뒤, 에디터에 손으로 옮기는 흐름이다.

병목은 세 곳이다.

1. **소재 발굴이 전부 수동이다.** 어떤 주제가 검색 수요가 있는지 데이터 없이 감으로 고른다.
2. **지침서가 단일 프롬프트에 뭉쳐 있다.** 본문 작법, 이미지 프롬프트, 검증 규칙이 한 덩어리라 매번 전체를 로드하고, 일부만 고치기 어렵다.
3. **이미지 제작이 프롬프트 전달에서 끊긴다.** 한글 텍스트 렌더링 실패 때문에 결국 사람이 캔바에서 다시 작업한다.

### 1.2 목적

강아지 니치 블로그 글 1건을, **소재 선정부터 붙여넣기 직전 패키지까지** 자동 생성한다. 최종 붙여넣기와 발행 버튼은 사람이 누른다.

### 1.3 성공 기준 (2단계 운영)

성공 기준은 블로그 단계에 따라 다르다. `blog-profile.yaml`의 `phase` 값이 이 전환을 제어한다.

| | Phase 1 — 승인 전 (현재) | Phase 2 — 승인 후 |
|---|---|---|
| **1차 목표** | 누적 발행량 확보 + 저품질 회피 | 검색 상위노출 + 조회수 |
| **키워드 난이도 상한** | 낮음 (롱테일 전용) | 중간까지 허용 |
| **단건 성공 판정** | 자체 검증 전 항목 통과, 사람 수정률 30% 미만 | 위 + 발행 후 30일 내 대상 키워드 검색 결과 1페이지 진입 |
| **실패 신호** | AI 티, 유사문서, 기사 요약 잔재 | 노출 미진입 키워드가 3연속 발생 |

Phase 1에서 "상위노출"을 1차 목표로 잡지 않는 이유: 34건 규모 블로그는 경쟁 키워드를 이길 수 없고, 그 상태에서 노출 지표로 성패를 판정하면 에이전트가 계속 실패로 기록된다. 이 구간의 실질 리스크는 순위가 아니라 **저품질 누적으로 인한 심사 탈락**이다. 따라서 검증 기준을 원본성과 완성도에 둔다.

> **수정률 계측 방식**: "사람 수정률 30% 미만"은 자동 diff 계산이 아니라, 발행 직후 사람이 남기는 **체감 수정도 self-report(1~5점)** 로 갈음한다. `publish.md`에 입력란을 두고(§2.2 S9), `history.jsonl`에 `revision_score`로 기록한다(§2.2 S10, §3.6). **이 값은 참고 로그로만 쓰며 자동 재시도나 실패 판정에 연결하지 않는다.** 자동 스크래핑 기반 diff 계산은 1인 운영 규모에 비해 유지보수 비용이 크므로 채택하지 않는다.

### 1.4 범위

**포함**
- 소재/키워드 발굴 및 데이터 기반 선별
- 경쟁글 분석과 콘텐츠 갭 도출
- 본문 초안 작성 (검색형 / 홈피드형 2트랙)
- 썸네일 및 본문 이미지 생성 (Canva)
- 자체 품질 검증
- 붙여넣기용 패키지 생성 (`post.html` + `images/` + `publish.md`)
- 발행 이력 기록 및 중복 방지

**제외**
- 자동 발행. 네이버 글쓰기 API는 2020년 5월 6일 종료됐고, 종료 사유가 기계적 대량 발행 차단이었다. 브라우저 자동화 발행은 게시물 운영정책 위반 소지가 있어 수익형 블로그에서 계정 리스크가 크다. **발행은 사람이 한다.**
- 댓글/이웃 관리, 통계 수집 자동화 (v2 이후)
- 이미지 최종 심미 판단 (사람 검토)

### 1.5 입력

| 구분 | 항목 | 형식 | 필수 |
|---|---|---|---|
| 상시 설정 | `blog-profile.yaml` — 니치, 톤, phase, 금지 표현, 블로그 URL | YAML | O |
| 상시 설정 | `history.jsonl` — 발행 이력 (제목, 키워드, 발행일, URL) | JSONL | O |
| 자격 증명 | 네이버 검색광고 API (`CUSTOMER_ID` / API Key / Secret Key) | `.env` | △ |
| 자격 증명 | 네이버 개발자센터 검색 API (`CLIENT_ID` / `CLIENT_SECRET`) | `.env` | O |
| 실행 시 | 시드 — 없음(자동 발굴) / 키워드 지정 / 기사 URL·원문 | 자연어 | X |

`.env`가 없으면 워크플로우 S2가 대체 경로로 분기한다. (§2.4)

### 1.6 출력

`/output/<YYYY-MM-DD>_<slug>/` 하위에 생성한다.

| 파일 | 내용 | 소비 주체 |
|---|---|---|
| `01_brief.json` | 확정 키워드, 검색량, 경쟁 분석, 콘텐츠 갭, 글 트랙 | 다음 단계 에이전트 |
| `02_draft.md` | 본문 초안 (이미지 삽입 위치 포함) | 다음 단계 에이전트 |
| `02_meta.json` | 제목 후보 8개, 태그, 검색 설명문, 소제목별 이미지 스펙 | 다음 단계 에이전트 |
| `03_audit.md` | 자체 검증 결과 (근거 인용 방식) | 사람 |
| `images/` | 썸네일 1장 + 본문 이미지 N장 (1200px 이상) | 업로드 스크립트 |
| `images.json` | 파일명, 공개 URL, 대체텍스트, 생성 파라미터 | 패키징 스크립트 |
| **`post.html`** | **이미지가 포함된 붙여넣기용 본문** | **사람 (핵심 산출물)** |
| **`publish.md`** | **발행 체크리스트** | **사람 (핵심 산출물)** |

### 1.7 제약조건

| ID | 제약 | 설계 반영 |
|---|---|---|
| C1 | 스마트에디터는 마크다운을 지원하지 않는다 | 최종 산출물을 HTML로 변환해 클립보드 붙여넣기 |
| C2 | 자동 발행 금지 | 워크플로우를 패키지 생성에서 종료 |
| C3 | 유사문서 판정 회피 | 원문 10어절 이상 중복 금지, 1차 출처 교차 확보, 중복 주제 사전 차단 |
| C4 | AI 생성 티 회피 | 실사 이미지 지시 + 자체 검증 항목 + 문체 규칙 |
| C5 | 반려동물 도메인 안전 | 수의학적 진단·처방 단정 금지, 응급 상황은 병원 안내로 귀결 |
| C6 | 한글 텍스트 이미지 렌더링 실패 | 배경 이미지와 텍스트 레이어 분리 |
| C7 | 검색광고 API는 HMAC-SHA256 서명 필요 | 스크립트가 서명 처리, 에이전트는 결과만 사용 |
| C8 | 발행 주기 미정 | 스케줄러 없음, on-demand 단건 실행 |
| C9 | 붙여넣기로 이미지가 따라오려면 이미지가 공개 https URL에 있어야 함. base64 삽입과 로컬 경로는 에디터가 차단 | 이미지 호스팅 단계(S8.5) 신설 |
| C10 | 네이버 블로그는 개별 글의 메타 설명 입력란이 없음. 본문 앞부분이 검색 결과 요약으로 자동 노출 | 첫 2~3문장에 주제가 드러나도록 작법 제약 추가 |

### 1.8 용어 정의

| 용어 | 정의 |
|---|---|
| **트랙** | 글의 유형. `search`(검색형) / `homefeed`(홈피드형) |
| **검색형** | 검색 수요가 확인된 키워드에 대해 상위글 대비 정보 갭을 메우는 글. 누적 자산형 |
| **홈피드형** | 기사·이슈를 생활 주제로 재정의한 이야기형 글. 단기 유입형. 기존 지침서 v3의 대상 |
| **포화도** | 블로그 문서 수 ÷ 월간 검색수. 낮을수록 경쟁이 덜함 |
| **콘텐츠 갭** | 상위 노출 글들이 공통적으로 다루지 않은 하위 주제 |
| **마커** | `[[IMG-01]]` 형태로 본문에 삽입되는 이미지 위치 표시자. S9 정상 경로에서는 쓰이지 않고, 붙여넣기 실패 시 폴백 경로에서만 쓰인다 |
| **phase** | 블로그 운영 단계. 1 = 애드포스트 승인 전, 2 = 승인 후. 전환은 자동 감지하지 않으며, 승인 통보를 받은 사람이 `blog-profile.yaml`에서 직접 값을 바꾼다 |
| **승인 게이트** | 사람의 확인 없이는 다음 단계로 넘어가지 않는 지점 |
| **수동 제작 지점** | 승인이 아니라 사람의 실제 작업(파일 제작)이 있어야 진행되는 지점. v1.6부터 S8의 썸네일 제작이 여기 해당 |

### 2.2 단계별 상세

#### S0. 시드 판별 및 트랙 결정

- **처리 주체**: 에이전트 판단
- **입력**: 사용자 발화, `blog-profile.yaml`
- **처리**: 입력에 기사 URL/원문이 있으면 `homefeed`, 키워드만 있으면 `search`, 아무것도 없으면 S1으로 보내 발굴 후 결정
- **분기 조건**:
  - 기사 존재 → `homefeed` 트랙
  - 키워드 존재 → `search` 트랙
  - 없음 → S1 진입, 발굴 결과에 뉴스 소재가 섞이면 `homefeed`, 정보성 키워드면 `search`
- **성공 기준**: 트랙과 시드가 확정됨
- **검증 방법**: 스키마 검증 (`track` 필드가 두 값 중 하나)
- **실패 시**: 에스컬레이션 — 사용자에게 시드 요청

#### S1. 소재 발굴

- **처리 주체**: 스크립트 수집 + 에이전트 선별
- **처리**:
  - 스크립트: 검색광고 API 연관키워드 확장(강아지 시드 키워드군에서), 네이버 검색 API 뉴스 최근 7일 반려동물 이슈 수집, 계절 키워드 캘린더 참조
  - 에이전트: 수집 결과 중 니치 적합성·시의성·글로 쓸 여지를 판단해 후보 5~10건 선별
- **성공 기준**: 후보 5건 이상, 각 후보에 선정 사유 1줄 포함
- **검증 방법**: 규칙 기반 (후보 수) + 스키마 검증
- **실패 시**: 자동 재시도 최대 2회 (시드 키워드군 교체) → 실패 시 에스컬레이션

#### S2. 검색량 검증

- **처리 주체**: 스크립트 (전량)
- **처리**: 후보별 월간 검색수(PC+모바일), 블로그 총 문서 수 조회 → 포화도 계산 → phase별 필터 적용

#### S8. 이미지 생성

- **처리 주체**: 본문 이미지 — 에이전트 기획 + Canva MCP(자동). 썸네일 — 에이전트가 문구까지 결정하고, **실제 제작은 사람이 캔바에서 직접** 한다.

  4. 전부 1200px 이상 확인 → `images/`
- **파일명 규칙**: 본문 이미지 `<핵심키워드>-01.jpg` 등, 썸네일은 `thumbnail.jpg` 고정
- **성공 기준**: 썸네일 1장(사람 제공) + 본문 이미지 = 소제목 수(자동), 전부 1200px 이상
- **검증 방법**: 규칙 기반 (파일 존재·해상도) + 사람 검토 (심미·실사감, 사람이 직접 만들었으므로 사실상 겸함)
- **실패 시**: 본문 이미지는 개별 재시도 1회 → 스킵+로그 (기존과 동일). **썸네일 수동 제작 지점은 재시도 개념이 없고, 사람이 파일을 저장할 때까지 무기한 대기한다** — 승인 게이트와 동일한 대기 방식

> **v1.6 변경 사유 — 품질 우선으로 재조정.** v1.5에서 PIL 직접 합성으로 전환했으나, 실제 결과물을 캔바 원본과 비교한 결과 품질 격차가 커서 (그라데이션 거칢, 외곽선 뭉개짐) 사용자가 수용하지 않았다. Canva Autofill(API 자동화)은 Enterprise 전용이라는 제약은 그대로이므로, 자동화와 품질 중 품질을 우선해 **썸네일 1장만 사람이 직접 만드는 하이브리드**로 재조정한다.

>
> **기존 캔바 설정 작업(브랜드 템플릿 등록 + 필드 태깅, 2026-09-05)이 헛수고가 아니다**: 애초 목적(API 자동 채우기)에는 못 쓰지만, 그 결과로 캔바 "대량 제작" 화면에서 표에 값 6개만 입력하면 바로 디자인이 나오는 상태가 만들어졌다. 이게 사람이 매번 직접 만드는 이 워크플로우를 1~2분 이내로 빠르게 만들어준다.
>
> `thumbnail-compositor`(PIL 합성) 스킬은 v1.5에서 만들었으나 이번 결정으로 **주 경로에서 제외한다.** 폐기하지 않고 코드는 남겨두되(향후 캔바 없이도 돌려야 하는 상황 대비 폴백), 정상 흐름에서는 호출하지 않는다.

#### S8.5 이미지 호스팅

- **처리 주체**: 스크립트 (전량)
- **배경**: 스마트에디터는 base64로 삽입한 이미지와 로컬 파일 경로를 차단한다. 붙여넣기로 이미지가 함께 들어가려면 **공개 https URL에 이미 올라가 있어야 한다.**

- **성공 기준**: 모든 이미지에 대응하는 https URL 존재, URL이 200 응답
- **검증 방법**: 규칙 기반 (HTTP 상태 코드 확인)
- **실패 시**: 자동 재시도 1회 → 실패 시 에스컬레이션. 이 단계가 실패하면 이미지 없는 글이 나가므로 스킵 불가

> **이미지 레포는 삭제하지 않는다.** 네이버가 붙여넣은 외부 이미지를 자기 서버로 재업로드하는지, 원본 URL을 계속 참조하는지 확정되지 않았다. 후자라면 레포 삭제 시 과거 글의 이미지가 전부 깨진다.
>
> 같은 이유로 **파일명 SEO 효과는 기대치를 낮춘다.** 재업로드 시 파일명이 바뀔 수 있다. 파일명 규칙은 비용이 0이므로 유지하되, 효과에 의존하는 설계는 하지 않는다.

#### S9. 패키징

- **처리 주체**: 스크립트 (전량)
- **처리**:
  - `02_draft.md` → `post.html` 변환. 굵게·목록·표는 그대로 유지 (검증에서 전부 통과)
  - **소제목은 `<h2>`를 쓰지 않는다.** 에디터가 h 태그의 폰트 크기를 자기 기본값으로 덮어써 본문과 구분이 사라진다. 대신 크기를 인라인으로 박은 형태로 출력한다: `<p><span style="font-size:24px; font-weight:bold;">소제목</span></p>`
  - **이미지를 `<img src="https://...">` 로 본문 해당 위치에 직접 삽입.** 마커는 사용하지 않는다
  - `publish.md` 생성: 제목 후보 3개, 태그 5~8개, 카테고리, 주제 분류(반려동물), 대표사진 지정, 검색 허용 ON 확인, 출처 한 줄, 미생성 이미지 경고, **발행 직후 체감 수정도 입력란(1~5점)**
- **성공 기준**: `post.html`이 브라우저에서 이미지 포함 정상 렌더, img 태그 수 = 생성 이미지 수
- **검증 방법**: 스키마 검증 (img/이미지 대조)
- **실패 시**: 자동 재시도 1회 → 실패 시 에스컬레이션

#### ★ 승인 게이트 2 — 사람

- **작업**: `post.html` 열기 → Ctrl+A, Ctrl+C → 로그인된 스마트에디터에 Ctrl+V (글과 이미지가 함께 들어감) → 제목 입력 → 대표사진 지정 → `publish.md` 체크리스트 적용 → 발행
- **예상 소요**: 1분 내외
- **근거**: C2. 자동 발행을 하지 않는 것이 이 시스템의 핵심 안전장치다. 로그인은 사람이 직접 하므로 자동화 차단 우회가 필요 없고, 계정 리스크가 발생하지 않는다.

> **검증 완료 (2026-09-03).** 이미지 3장 + 표 + 불릿 목록 + 굵게 + 순서가 포함된 테스트 문서를 실제로 붙여넣어 확인했다.
>
> | 항목 | 결과 |
> |---|---|
> | 이미지 (공개 URL 참조) | 전부 전송됨 |
> | 이미지 순서 | 유지 |
> | 표 | 표 형태 유지 |
> | 불릿 목록 | 유지 |
> | 굵게 | 유지 |
> | **소제목 (`<h2>`)** | **크기가 본문 수준으로 뭉개짐 → S9에서 인라인 스타일로 대체** |
>
> 마커 방식은 폴백으로만 보존한다. 향후 에디터 UI 변경으로 이미지 전송이 막히면 그때 복귀한다.
>
> **미확정 항목**: 네이버가 붙여넣은 외부 이미지를 자기 서버로 재업로드하는지 여부. 확인 전까지는 보수적으로 **이미지 레포를 영구 보관**한다. 붙여넣은 이미지를 클릭했을 때 네이버 이미지 편집 도구가 뜨면 재업로드된 것이며, 그때 이 규칙을 완화할 수 있다.

#### S10. 이력 기록

### 3.3 에이전트 구조

**서브에이전트 분리를 채택한다.** 근거는 두 가지다.

1. **컨텍스트 최적화.** 기존 지침서 v3 단독으로도 상당한 분량이고, 여기에 검색형 작법·이미지 규칙·검증 규칙·도메인 안전 규칙이 더해진다. 전부 상시 로드하면 매 단계 낭비가 크다. 본문 작성 시점에 작법 지침만, 이미지 시점에 이미지 지침만 로드한다.
2. **도메인 분리가 명확.** 키워드 데이터 분석, 국어 작문, 시각 디자인, 품질 감사는 서로 다른 판단 기준을 쓴다. 한 컨텍스트에 섞으면 기준이 오염된다.

| 서브에이전트 | 역할 | 담당 단계 | 입력 | 출력 | 참조 스킬 |
|---|---|---|---|---|---|
| **keyword-scout** | 소재 발굴, 수요 검증, 경쟁 분석, 브리프 확정 | S1~S5 | `blog-profile.yaml`, `history.jsonl`, 시드 | `01_brief.json` | naver-keyword-api, naver-serp-collector, keyword-scoring, duplicate-check |
| **post-writer** | 트랙별 본문 작성 | S6 | `01_brief.json` 경로 | `02_draft.md`, `02_meta.json` | homefeed-writing, search-post-writing, pet-domain-guard |
| **quality-auditor** | 자체 검증, 재작성 지시 | S7 | `02_draft.md` 경로, `01_brief.json` 경로 | `03_audit.md` | self-audit, pet-domain-guard |
| **visual-producer** | 본문 이미지 기획·생성(자동), 썸네일 문구 결정 후 사람에게 전달 및 대기, 완료된 파일 호스팅 | S8~S8.5 | `02_meta.json` 경로 | `images/`, `images.json` (공개 URL 포함) | canva-visuals, image-uploader (thumbnail-compositor는 폴백 전용) |

**호출 규칙**: 서브에이전트 간 직접 호출을 금지한다. `quality-auditor`가 재작성이 필요하다고 판단하면 결과를 메인에 반환하고, 메인이 `post-writer`를 다시 호출한다.

**quality-auditor를 별도로 둔 이유**: 자기가 쓴 글을 같은 컨텍스트에서 검사하면 방금 내린 결정을 정당화하는 쪽으로 기운다. 초안만 받아 규칙과 대조하는 별도 컨텍스트가 위반을 더 잘 잡는다.

| `thumbnail-compositor` | 스크립트 (폴백 전용) | Pillow로 배경 사진 위에 텍스트 직접 렌더링. v1.6부터 정상 흐름에서 호출되지 않음 — 향후 필요 시에만 수동 실행 | 미사용 (보존) |
| `image-uploader` | 스크립트 | 이미지를 GitHub 공개 레포에 push하고 공개 URL 반환, 응답 검증 | S8 완료 직후 (S8.5) |
| `self-audit` | 지침 | 검증 7항목(문체 세부 체크 5종 포함), 근거 인용 강제 형식 | S7 진입 시 항상 |
| `naver-packager` | 스크립트 | md → html 변환, 이미지 URL 삽입, `publish.md` 생성 | S9 진입 시 |

**스킬 vs 서브에이전트 구분 기준**: 위 10개는 전부 도구·규칙 단위이며 여러 에이전트가 공유한다(`pet-domain-guard`는 post-writer와 quality-auditor가 공유). 역할·책임 단위인 4개는 서브에이전트로 뒀다.

### 3.5 데이터 전달 방식

**파일 기반을 기본으로 한다.** 메인은 서브에이전트에 `/output/<slug>/01_brief.json` 같은 **경로만** 넘기고, 서브에이전트가 직접 읽는다. 브리프·초안·메타는 모두 구조화된 데이터이고 분량이 커서 인라인으로 넘기면 메인 컨텍스트가 매 단계 누적된다.

**프롬프트 인라인은 두 경우에만 쓴다.**
- 승인 게이트에서 사람에게 요약 제시할 때
- `quality-auditor`가 재작성 지시를 반환할 때 (위반 문장 목록은 짧다)

### 3.6 주요 산출물 파일 형식

| 파일 | 형식 | 핵심 필드 / 구조 |
|---|---|---|
| `blog-profile.yaml` | YAML | `niche`, `phase`, `tone`, `banned_expressions`, `blog_url`, `seed_keywords` |
| `history.jsonl` | JSONL | `{date, title, keyword, track, url, revision_score}` — `revision_score`는 1~5, 참고 로그 전용 |
| `01_brief.json` | JSON | `track`, `keyword`, `volume`, `saturation`, `volume_source`, `competitors[]`, `gaps[]`, `primary_sources[]`, `audience`, `core_question`, `outline[]`, `title_candidates[]` |
| `02_draft.md` | Markdown | 제목 + 소제목 3~5 + 본문 + 이미지 삽입 위치 + 출처 1줄 |
| `02_meta.json` | JSON | `titles[8]`, `hashtags[]`, `thumbnail_copy{line1..3, sub}`, `image_specs[]` |
| `03_audit.md` | Markdown | 검증 7항목 각각에 위반 문장 인용 또는 "없음" |
| `images.json` | JSON | `[{position, filename, public_url, alt, source, status}]` |
| `post.html` | HTML | 인라인 스타일 적용 본문 + `<img src="https://...">` 삽입 완료 |
| `publish.md` | Markdown | 제목 후보 3, 태그, 카테고리, 주제 분류, 대표사진, 검색 허용 확인, 경고 |

## 4. 설계 판단 근거 요약

사용자가 명시하지 않아 에이전트가 판단한 항목들이다.

| 항목 | 판단 | 근거 |
|---|---|---|
| 성공 기준을 2단계로 분리 | 채택 | 34건 블로그에 상위노출 기준을 적용하면 전 사이클이 실패로 기록됨. 승인 전 실질 리스크는 순위가 아니라 저품질 누적 |
| 검색형 트랙 신설 | 채택 | 애드포스트 수익은 검색 유입 누적이 자산. 기사 기반 단일 트랙은 유사문서 위험도 더 높음 |
| 기존 지침서 v3 유지 | 채택 (홈피드 트랙 한정) | 홈피드 랭킹 로직 대응과 검증 항목 설계가 완성도 높음. 폐기할 이유 없음 |
| 이미지 텍스트 분리 | 채택 | 지침서가 이미 예외 조항으로 인정한 실패 지점. 예외를 기본 경로로 승격 |
| 서브에이전트 4개 분리 | 채택 | 지침 총량이 크고 도메인이 분리됨. 컨텍스트 최적화 목적 |
| quality-auditor 독립 | 채택 | 작성자와 같은 컨텍스트의 자기검증은 자기 정당화로 기움 |
| 승인 게이트 2곳 | 채택 | 게이트 1은 낭비 방지, 게이트 2는 계정 안전. 둘 다 제거 불가 |
| 스케줄러 없음 | 채택 | 발행 주기 미정. on-demand 단건 실행이 적합 |
| 자동 발행 제외 | 채택 | 글쓰기 API 종료 사유가 기계적 대량 발행 차단. 계정 리스크 대비 이득 없음 |
| 이미지 GitHub 호스팅 | 채택 | 붙여넣기로 이미지가 따라오려면 공개 URL 필수. push 한 줄이면 되고 사람 손이 0 |
| 마커 방식 폐기 | 채택 (폴백 보존) | 이미지 개별 삽입은 반자동화의 이득을 상쇄. 1차 테스트 실패 시에만 복귀 |
| 브라우저 자동화 기각 | 채택 | 공개 구현들이 자동 로그인 차단을 우회하고 절대 XPath에 의존. 복붙과의 시간 차는 1분, 대가는 계정 리스크와 상시 유지보수 |

| 썸네일 수동 제작 하이브리드 | 채택 (v1.6) | 본문 이미지(텍스트 없음)는 계속 완전 자동 — Enterprise 제약과 무관. 썸네일 1장만 사람이 캔바 대량 제작으로 직접 제작. 앞서 해둔 필드 태깅이 이 워크플로우를 1~2분으로 단축시켜줌. 자동화보다 품질을 우선한 사용자 선택 |
